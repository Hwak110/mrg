# Skill: SVG Executive Topology Paint Engine（Hwak110 定制）

## 适用场景

当用户要求绘制 SVG 架构图、SVG 拓扑图、系统设计图或高层技术汇报图时，使用本 Skill。普通网页界面、交互原型和需要动态布局的图表不强制使用本 Skill。

## 1. 原生矢量与正交网格

- 输出可直接保存为 `.svg` 并在浏览器中打开的 XML 文档，根元素使用 `xmlns="http://www.w3.org/2000/svg"`。
- 连线必须使用 `<path>`、`<line>` 或 `<polyline>`。路径只允许 `M` 和 `L` 指令，禁止使用贝塞尔曲线 `C`、`Q`、`S` 和弧线 `A`。
- 所有转折点保持 90 度；优先通过固定 `viewBox`、明确坐标和对齐锚点建立网格。
- 同一层级的并列、无状态组件不互相连线；通过统一卡片尺寸、间距和坐标表达平级关系。
- 需要表达方向时使用明确的箭头标记，并避免让标签压在线上或遮挡节点。

## 2. 层级与边界

- 使用 `<g>` 对逻辑层、边界和组件分组，并为每个边界提供清晰的标题。
- 典型层级可以包括入口或控制面、计算或 Agent 沙箱、契约与产物、质量门禁、持久化数据层；根据实际系统裁剪，不强行套用。
- 用实线表示核心同步请求、强依赖或状态变更；用虚线表示契约读取、异步事件、监控、日志和审计等弱依赖或旁路流量。
- 物理沙箱边界只表达职责和上下文隔离；除非实现已明确采用容器或进程隔离，不得把它描述成已经存在的安全边界。

## 3. 语义化样式

在 `<defs><style>` 或等价的类定义中集中管理样式，保持直角、低饱和度和足够对比度。默认可使用以下配色：

```css
.ortho-line { stroke: #cbd5e1; stroke-width: 2; fill: none; }
.ortho-dotted { stroke: #94a3b8; stroke-width: 2; stroke-dasharray: 6 4; fill: none; }
.ortho-heavy { stroke: #2563eb; stroke-width: 2.5; fill: none; }
.ingress { fill: #f4f4f5; stroke: #d4d4d8; }
.compute { fill: #eff6ff; stroke: #bfdbfe; }
.quality-gate { fill: #fef2f2; stroke: #fca5a5; }
.storage { fill: #f0fdf4; stroke: #bbf7d0; }
```

颜色表达语义而非装饰：蓝色用于计算，红色用于风险或门禁，绿色用于持久化，灰色用于入口和控制。避免渐变、阴影、无意义图标和单一颜色铺满全图。

## 4. 输出与校验

- 在 SVG 内提供标题、必要的副标题和图例；文本必须说明线型、边界和关键组件含义。
- 视图应包含稳定的 `viewBox`，并在常见浏览器中保持清晰。不得依赖外部字体、脚本或远程图片才能显示核心内容。
- 输出前检查 XML 是否闭合、所有引用的 `id` 是否存在、文本是否超出卡片、路径是否包含禁用指令，以及连线是否穿过无关节点。
- 同步提供 SVG 文件路径和简短的架构说明；不要把实现细节伪装成已部署能力。
